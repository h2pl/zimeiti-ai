# 运营归因层（ops-review）

> 五层流程第五层：**归因**。目标——用真实发布数据回答「什么有效、下一步做什么」。
> 上一层：`ops-publish`。

## 触发条件

用户要求复盘/看数据/定下期策略时先读本 SKILL。

## 数据源（按优先级）

1. `outputs/_analytics/<platform>/<date>.json`——本系统落盘的**发布事实**记录
   （media_id / 内容路径 / 状态 / 发布日期；由发布层自动写入）
2. 平台侧阅读/互动数据——当前版本**未接入**（需凭据与拉取任务，见变更范围说明）；
   缺失时如实说明，不编造读数

## 执行步骤

1. **读记录**：`read_records` 视角=读 `outputs/_analytics/` 下全部 JSON。
2. **无记录** → 明确报告「暂无已发布内容记录」，说明需要什么数据才能复盘
   （接入平台阅读数据 / 先完成一次发布），**不得编造任何数字**。
3. **有记录** → 结构化复盘：
   - 已发布清单（标题/平台/日期/状态）
   - 节奏观察（发布间隔、断更缺口）
   - 给下一轮内容策略 1-3 条具体建议（主题方向/节奏/形式）

## 产物约定

- 复盘结论（清单 + 观察 + 建议），按需落盘 `outputs/复盘-<日期>.md`

## 交接条件

复盘结论交付 → 本轮五层闭环完成；新的策略建议可回流 `ops-discover` 开始下一轮。
