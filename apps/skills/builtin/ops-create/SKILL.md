# 运营制作层（ops-create）

> 五层流程第三层：**制作**。目标——产出一篇过质检、可直接进发布流程的初稿。
> 上一层：`ops-plan`；下一层：`ops-publish`。

## 触发条件

用户要求写作/成稿/做内容时先读本 SKILL。

## 执行步骤

1. **锁定输入**：选题标题 + 推荐角度（来自策划层）+ 画像 `style.md`（口吻/句式/人称）。
2. **成稿**（结构照此）：
   - `# 标题` → `> 一句话摘要` → 正文（`##` 二级、`###` 三级，最多两层）
   - 开头必须有钩子（痛点/反常识/场景，三行内抓住人）
   - 段落短（手机端可读）；技术概念配**可运行**例子
   - 结尾 1-3 句总结 + 自然行动引导（关注/系列/往期）
3. **四项质检自检**（缺一不可交付）：
   - [ ] 钩子：前三行内出现，且与正文兑现相关
   - [ ] 字数：1200-1800 字（不足补深度，超出砍废话）
   - [ ] 格式：层级 ≤ 两层、代码块语言标注、无大段无换行
   - [ ] 数据边界：无编造数字；版本/日期不确定就不写具体值
4. **落盘**：write_file 到 `outputs/<英文短横线命名>.md`（内容库唯一可写区）。
5. **脚本化质检**（可用 exec_script 调用，注册表内）：
   - `ai_score`（位置参数=文章路径）：AI 味/质量评分，🟢 PASS 再交付
   - `content_guard`（子命令 `scan`，`--file` 文章路径）：出站前敏感信息扫描，
     BLOCK 级命中（退出码 7）必须改稿

## 产物约定

- `outputs/<slug>.md` 完整 Markdown 成稿
- 命名建议：主题短横线（如 `agent-memory-design.md`）

## 交接条件

四项质检全过 + 成稿落盘 → 进入 `ops-publish`（发布层上传草稿）。
