# ops-metrics Specification

## Purpose
统一管理各平台发布事件与其互动指标的时间序列快照，为运营复盘与内容策略校准提供唯一权威数据源。

## Requirements

### Requirement: 发布事件记录
发布成功后，系统 MUST 记录一条发布事件（平台、标题、内容类型、来源目录、发布链接、发布日、所属画像与选题方向）；同一来源目录 + 同一发布日重复记录 MUST 更新既有行而非插入新行。发布失败时 MUST 记录事件并注明原因，不静默丢弃。

#### Scenario: 发布成功后落库
- **GIVEN** 一篇草稿已在某平台发布成功
- **WHEN** 记录发布事件
- **THEN** 事件表出现一条记录，含平台/标题/链接/发布日/画像/选题方向

#### Scenario: 同日重复记录更新而非插入
- **GIVEN** 该来源目录与发布日的事件已存在
- **WHEN** 再次记录同一发布
- **THEN** 更新既有行（覆盖标题/链接），不新增行

### Requirement: 指标快照回收
系统 MUST 能按平台回收互动指标快照：公众号 MUST 通过已 vendor 的 wechat-mp-toolkit datacube 接口取数（用户增减、图文阅读、转发分享等）；小红书 MUST 通过自有创作者中心页面读取账号级指标。快照 MUST 带采集时间戳与来源标记；采集失败 MUST 记录失败原因并保留历史值，不得用零值覆盖真实数据。

#### Scenario: 快照写入项目数据库
- **GIVEN** 一次取数完成
- **WHEN** 写入快照
- **THEN** 数据写入项目 Postgres（`DATABASE_URL`）的 metric_snapshots 表，不引入第二套 SQL 引擎

#### Scenario: 公众号 datacube 取数
- **GIVEN** 公众号有效凭据与日期区间
- **WHEN** 回收公众号指标
- **THEN** 快照记录用户增减与图文阅读/转发数据，附采集时间与来源（datacube）

#### Scenario: 小红书创作者中心取数
- **GIVEN** 小红书登录态有效
- **WHEN** 回收小红书指标
- **THEN** 快照记录账号级指标（关注数/粉丝数/获赞与收藏/曝光数/观看数/点赞数等），附采集时间与来源（creator-center）

#### Scenario: 采集失败保留历史
- **GIVEN** 某次采集接口异常
- **WHEN** 写入快照
- **THEN** 记录失败原因，不将既有指标覆盖为零

### Requirement: 只读归因查询
归因查询 MUST 为只读操作（不修改事件与快照），结果由确定性脚本计算（趋势、内容生命周期判定如速爆型/稳增型/长尾型），系统 MUST NOT 让模型手工估算数值。

#### Scenario: 查询趋势与生命周期
- **GIVEN** 存在多次指标快照
- **WHEN** 执行归因查询
- **THEN** 输出按平台/画像的趋势与单篇内容生命周期判定，数据来自快照而非估算

#### Scenario: 查询不回写
- **GIVEN** 执行任意归因查询
- **WHEN** 查询完成
- **THEN** 事件与快照数据保持不变

### Requirement: 运营数据报告页
系统 MUST 能从运营数据（发布事件、指标快照）确定性生成自包含 HTML 报告页，包含：KPI 卡（最新粉丝数、获赞与收藏、事件数、快照数、生命周期分布）、趋势图表（SVG）、发布事件表与洞察区。生成 MUST 为只读（不修改数据），文件 MUST 可离线打开（无外部资源依赖）。缺数据的指标 MUST 显示「无数据」而非零值。

#### Scenario: 生成报告页
- **GIVEN** 存在发布事件与指标快照
- **WHEN** 生成报告页
- **THEN** 输出自包含 HTML，含 KPI 卡、SVG 图表、事件表，数值与数据源一致

#### Scenario: 无数据显示而非零值
- **GIVEN** 某指标无任何快照
- **WHEN** 生成报告页
- **THEN** 该指标显示「无数据」

#### Scenario: 生成只读
- **GIVEN** 生成报告页
- **WHEN** 完成
- **THEN** 事件与快照数据保持不变
