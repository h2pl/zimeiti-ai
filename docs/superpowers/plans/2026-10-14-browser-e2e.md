# Plan: browser-e2e — 浏览器级双端对齐 E2E 套件

目标：把单文件浏览器 E2E 重组为 `apps/e2e/` 独立目录，覆盖每个用户路径（10 场景），LLM 在 OpenAI 兼容端点 mock，其余链路真实；双端（zimeiti/Easel）结构级对齐。

## 验收命令

- `cd apps/api && uv run python ../e2e/run.py` → 全场景 PASS、双端差异 0、退出码 0
- 连续 3 轮同结果
- `make check`（既有门禁）全绿

## 任务分组（对应 tasks.md #1.1–#4.3）

### G1 骨架（1.1–1.5）

`runner.py`（TargetManager：spawn zimeiti with mock env / spawn Easel / readiness / teardown 强杀+端口核对）、`mock_llm.py`（uvicorn 线程 `/v1/chat/completions` SSE 流，按消息返回 `MOCK:` 前缀确定性回复）、`helpers.py`（click_nav role→text 兜底、onboarding 轮询、expect_response 同步封装、poll、sweep）、`parity.py`（结构级 diff + NOTE）、`coverage_map.py`、`scenarios/base.py`、`run.py`（`--scenarios`、`--target`、退出码）。

RED 证据：骨架完成后跑 `run.py`——此时仅迁移 S1/S2/S3/S5 四场景可通，新场景（S4/S6-S10）尚不存在或 FAIL。

### G2 场景迁移与新增（2.1–2.10）

从单文件迁移 S1/S2/S3/S5（行为等价重构）；新增 S4（排期→日历）、S6（内容库预览，runner 预置 fixture）、S7（画像向导全链路，mock LLM 增强）、S8（账号 whoami）、S9（设置模型通道）、S10（热点条件断言+做内容跳转）。每场景网络同步断言。

GREEN 证据：`run.py --scenarios` 逐场景通过；全量双端差异 0。

### G3 集成（3.1–3.3）

删 `apps/scripts/browser_e2e.py`；Makefile `e2e-browser` 改指 `cd apps/api && uv run python ../e2e/run.py`；`apps/e2e/README.md`；ruff 检查 apps/e2e（按需豁免 E402 等测试场景惯例）。

### G4 验证（4.1–4.3）

全量 3 轮 + 数据残留检查（两端 outputs/profiles/ideas store）+ `make check` + 双服务 E2E parity 57 项不回归。
