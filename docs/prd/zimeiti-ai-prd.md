# 目标

做一个**自媒体 Agent**：把「选题 → 创作 → 发布 → 复盘 → 获客」的重复劳动交给 agent，用户只在关键节点确认。能力目标是 **Easel 与 xiaobei 两个参考项目的并集**——既具备 Easel 的内容工作流能力（pipeline、技能、画像、产物、归因、发布读回），也具备 xiaobei 的托管运营与获客能力（24h 托管、评论区获客、智能客服、DNA 复刻、多平台分发、IM 通道）。

问题组合与主次：**没时间运营（首要）> 创作瓶颈 > 获客转化难**。北极星指标 = 用户每周运营耗时相对全手工基线的节省量。

双形态定位：Web 工作台（人主导）与 24h 托管（agent 主导 + 人审批）**共用同一套执行图**。

商业模式：先自用打磨，跑通后按订阅 SaaS（多租户）商业化。

# 定位与能力总览

产品能力 = **Easel（工作流形态）∪ xiaobei（托管运营与获客形态）**。

| 能力域 | Easel 提供 | xiaobei 提供 | 本产品要求 |
|---|---|---|---|
| 对话工作台 | 流式对话 + 工具事件 + 提问卡 | 微信/飞书/企微 IM 通道 | 两种入口共用同一执行图 |
| 技能与执行 | SKILL 流水线、技能库 | crews 多 agent 编排、skills | deepagents 运行时统一承载 |
| 账号与画像 | 扫码登录、whoami、画像六维 | 多平台账号、DNA 级复刻 | 账号体系 + 画像 + DNA 复刻 |
| 内容生产 | 选题库、热点雷达、图文创作 | 图文/海报/视频生成、爆款仿写 | 图文起步，逐步支持海报与视频 |
| 内容资产 | 内容库（产物/素材/文件树） | 已发布作品库 | 统一产物库（含合规结论） |
| 发布 | 发布中心、排期日历、读回对账 | 多平台分发（视频号/抖音/小红书/微博/知乎/X） | 首发小红书 + 公众号，逐步扩平台 |
| 数据与复盘 | 拆爆款、创作数据归因 | 数据监控、每日定时复盘 | 取数 + 归因 + 每日复盘 |
| 托管运营 | — | 24h 托管循环、定时触发 | 托管循环 + 人工闸门 |
| 获客 | — | 评论区获客、智能客服、潜客挖掘、Smart Search | 阶段二实现 |
| 合规与风控 | content_guard | 风控事故教训、频控 | fail-closed 合规 + 风控护栏 |

# 实施路径（分阶段，按序推进）

## 阶段一：复制实现 Easel（当前阶段）

目标是把 Easel 的能力原样落到本项目，作为能力底座：

1. **前端**：整份拷贝 Easel 前端源码（`components/`、`lib/`、`styles/`、静态资源）作为 UI 基线，逐文件一致、可持续与 Easel 同步
2. **后端**：实现 Easel 的前端契约端点，运行时代替 OpenClaw 的是 **deepagents**（zimeiti 后端已是 `create_deep_agent` + `ask_human` HITL）；Easel 后端中不依赖 OpenClaw 的部分（persona、outputs、upload、settings、accounts 等路由）可直接复用其实现，依赖 OpenClaw 的模块（`openclaw_cmd`、`openclaw_workspace`、`gateway_endpoint`、`gateway_questions`、`local_agents`、`commands/*`）用 deepagents 重写
3. **验收**：功能与 Easel 完全一致（对话流式、工具事件、提问卡、技能库、内容库、账号、画像、选题、日历、发布、拆爆款）

## 阶段二：实现 xiaobei 能力

在阶段一底座上补齐 xiaobei 侧能力：24h 托管循环与定时调度、评论区获客、智能客服、赛道头部账号 DNA 复刻、视频与多平台分发、Smart Search 情报源、IM 通道（微信/飞书/企微）。

## 阶段三：商业化

多租户、计费与计量埋点、订阅与权限。

# 首版（阶段一 MVP）范围

- 对话工作台（流式、工具事件可见、提问/审批内联卡片）
- 技能库（运维技能与 Agent 工具清单，可参数化触发）
- 内容库（产物归档、正文查看、合规结论）
- 账号与画像（启停、凭证、画像六维编辑）
- 选题看板与热点（选题卡流转）
- 内容日历与发布中心（排期、预检、入队、读回对账）
- 拆爆款与创作数据（复盘规律、指标基线）
- 托管循环骨架（定时/事件触发，审批点外自动）
- 审计日志（全链路事件）

# 非目标

- 不自研底层模型
- 不做通用 coding agent
- 不做平台方官方 API 的替代
- **不引入 OpenClaw 作为运行时依赖**（Easel 源码仅作契约与实现参考）
- 阶段一不做：获客侧（评论区截流/智能客服/潜客挖掘）、视频与多平台分发、DNA 复刻、多租户与计费
- 首版内容形态为图文；短视频后续迭代

# 验收示例

**阶段一（对齐 Easel）**

- **A1 对话与工具可见**：用户发起创作指令 → 流式返回内容，工具调用过程可见
- **A2 提问卡**：agent 执行中提问 → 对话内出现选项卡片，回答后续跑
- **A3 审批边界**：agent 尝试未获审批的发布动作 → 阻断并等待人工确认
- **A4 产物归档**：创作完成 → 产物入内容库，含合规结论与正文
- **A5 发布 HITL**：用户在审批点确认 → 发布到目标平台
- **A6 未核实不报成功**：发布已执行但读回对账失败 → 标记 `unverified` 而非成功
- **A7 前端一致性**：关键页面截图与 Easel 对应页面一致（布局、间距、组件外观）

**阶段二（对齐 xiaobei，后续）**

- **X1 托管循环**：无人值守下定时完成一轮选题→创作→待审
- **X2 评论区获客**：识别评论区潜在客户并进入跟进
- **X3 智能客服**：7×24 售前接待
- **X4 DNA 复刻**：输入头部账号 → 产出风格 DNA 并用于创作
- **X5 多平台分发**：一次创作分发到视频号/抖音/小红书等
- **X6 IM 通道**：通过微信/飞书/企微指挥 agent

# 约束与不变量

- 发布前必须人工确认（HITL），未确认不执行任何对外发布动作
- 平台凭证加密存储，不落明文、不入日志、不入代码库
- 平台自动化内置风控护栏（频控/操作白名单/高危平台标注），禁止伪造登录态
- 出站内容必须通过 **fail-closed** 合规审查（系统级强制，非 prompt 约束）
- 前端以 Easel 源码为基线，逐文件一致；不得为适配后端而改写拷贝来的前端代码
- 后端运行时为 deepagents，不引入 OpenClaw
